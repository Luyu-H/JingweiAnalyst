# Plan

1. Open the CMIP6 historical files for CESM2, GFDL-ESM4 and MPI-ESM1-2-LR. Read monthly `thetao`, `so`, `mlotst` for 1971-01 to 2000-12 and each model's fixed `areacello`; keep each model's native ocean grid, 2-D lat/lon, depth levels and time. Report any model-variable that is missing.
- Note [missing-values-and-land-cells]: Build each field's valid mask from the field itself because `thetao`, `so` and `mlotst` masks can differ; use NaN-aware reductions with weights masked to the same cells; treat values near 1e20 as unmasked fill, not as results.

2. For each model and each of the 30 Marches and 30 Septembers, compute the operator MLD from that month's `thetao`/`so` profile at every ocean column. Derive pressure from model depth and latitude; convert practical `so` to Absolute Salinity and `thetao` to Conservative Temperature; compute potential density anomaly sigma0; use the shallowest model level as the reference; find the first level where sigma0 minus sigma0 at the reference level reaches 0.03 kg m-3; linearly interpolate the crossing depth between the bracketing levels. If the threshold is never reached, set operator MLD to missing and retain its area for the exclusion report.
- Note [cmip6-mlotst-definition]: Pass `ref_depth` as the model's shallowest level; compute MLD of each monthly profile, never of the 30-year mean `thetao`/`so`; state the three residual causes versus `mlotst` (reference level, density form as a displaced parcel at local pressure versus a sigma0 difference, and time averaging of monthly profiles, which tends to make the operator MLD shallower); exclude columns where the threshold is never reached and report the excluded area, noting that GFDL-ESM4 and MPI-ESM1-2-LR often fill such columns near full column depth and CESM2 often gives 0 m.
- Note [cmip6-thetao-potential-temperature]: `thetao` is potential temperature referenced to 0 dbar; use the potential-temperature route in the density calculation, not an in-situ-temperature route.
- Note [cmip6-so-practical-salinity]: `so` is practical salinity with units string `0.001`; do not multiply by 0.001 or 1000, since the values are already of order 35; convert S_P to S_A before calling gsw routines that expect Absolute Salinity.

3. For each model and calendar month (March, September), build the 30-member all-time-valid mask where both operator MLD and published `mlotst` are finite in every one of the 30 instances; apply it and average each field over the 30 values plainly. Do this separately for March and September, producing the two climatologies and the common mask per model/month.
- Note [monthly-means-are-time-averages]: f(monthly mean) is not the mean of f: the operator computes the diagnostic first on monthly profiles, which is not the model's online time-mean MLD; state this order explicitly and do not attribute the residual to model error. Day weights do not enter a monthly climatology: average each calendar month's 30 values plainly.

4. On each model's native grid, form D = operator MLD climatology minus `mlotst` climatology for March and September. Build one common comparison mask over both climatologies with `build_comparison_mask`, pass `ocean_only=False`, apply it with `.where(mask)`, and report the number of common-mask cells. Compute area-weighted mean difference, area-weighted RMSE, area-weighted spatial Pearson correlation, the area percentage with absolute D exceeding 20 m as a share of common-mask area, and common-mask area as a percentage of total ocean area (sum of `areacello` over all model ocean cells). Use `areacello` weights masked to the common-mask cells; do not use plain cell averages.
- Note [common-comparison-mask]: Put both fields on one grid per model, build one mask over both with `build_comparison_mask` and apply it with `.where(mask)` before any bias, RMSE or correlation; report the mask cell counts alongside the metrics; `ocean_only=False` is correct because WOA23 is not part of this comparison.
- Note [omip-weighted-means-and-integrals]: Area-weight every map statistic with `areacello`; correlation needs `weighting='area'`; the exceedance-fraction percentage must be a share of area, not of cells.

5. Rank the three models from most to least internally consistent using the area-weighted RMSE averaged over the March and September cases as the primary criterion (lower RMSE means more consistent), with absolute mean difference and the exceeding-20-m area as secondary diagnostics. Report the criterion explicitly. Use the Figure 1 maps and area-weighted geographic summaries from the native-grid D fields to describe where disagreement concentrates.

6. Figure 1: a 3-by-2 panel with rows CESM2, GFDL-ESM4 and MPI-ESM1-2-LR and columns March and September, showing maps of D. For display only, conservatively remap each model's native field and mask to a coarser regular longitude-latitude grid using `areacello`; keep all metrics on native grids. Use a common geographic frame, a single shared diverging colour scale centred on zero with symmetric limits, coastlines and one shared colorbar.
- Note [omip-native-grid-vs-regridded]: Regrid only for the displayed cell-by-cell maps; compute means, integrals and all metrics on each model's own grid with its own cell areas; state the display regrid method as conservative remapping to a coarser regular grid, and do not use inter-model regridding for the metrics.

7. Figure 2: a 3-by-2 scatter panel in the same layout, x = operator MLD and y = `mlotst`, one point per common-mask ocean cell. Use logarithmic axes with identical x and y limits and tick locations in every panel, a dashed y = x line, and annotate each panel with its area-weighted bias, RMSE and correlation (the same numbers as step 4).

8. Report the six model-and-month result sets to the requested precision: mean difference and RMSE to 0.1 m, correlation to 0.001, exceeding-20-m area percentage and coverage percentage to 0.1 percent, plus the ranking, the regional description and the non-crossing excluded-area report.

Other notes:
- Logarithmic scatter axes cannot display zero or negative values; any such common-mask cells are omitted from Figure 2 only, with the count reported, while all metrics use the full common mask.
- Common-mask coverage and non-crossing excluded area differ by model and month; report them with the metrics so the ranking is not read as a comparison over identical areas.
- The maps are remapped only for display; all numerical results are computed on native grids.
